Первые четыре строки совпадают. Разница в последней строке: `document` — это не часть
языка JavaScript, а объект, который **браузер** предоставляет для работы со страницей (DOM).
Node.js не создаёт HTML-страницу, поэтому переменной `document` там нет и
`typeof document` возвращает `"undefined"` (без ошибки, так как `typeof` для необъявленного
имени ошибку не выбрасывает).

## 5. Задание 2. Типы и преобразования

| Выражение | Ожидание до запуска | Фактическое значение | Тип результата | Объяснение |
|---|---|---|---|---|
| `"8" + 2` | `"82"` | `82` | string | Если один операнд `+` — строка, выполняется конкатенация: число 2 превращается в `"2"`. |
| `"8" - 2` | `6` | `6` | number | Оператор `-` определён только для чисел, поэтому `"8"` неявно преобразуется в 8. |
| `Number("8") + 2` | `10` | `10` | number | Явное преобразование: оба операнда числа — обычное сложение. |
| `"12" > "3"` | `false` | `false` | boolean | Строки сравниваются посимвольно: `"1"` (код 49) меньше `"3"` (код 51). |
| `12 === "12"` | `false` | `false` | boolean | Строгое равенство не приводит типы: number ≠ string. |
| `Number("")` | `0` | `0` | number | Пустая строка (и строка из пробелов) по правилам `Number()` даёт 0, а не `NaN`. Поэтому `Number()` — не проверка ввода. |
| `Number("text")` | `NaN` | `NaN` | number | Непреобразуемая строка даёт `NaN` («не число»), но сам `NaN` имеет тип number. |
| `Boolean("false")` | `true` | `true` | boolean | Любая непустая строка истинна; текст «false» не интерпретируется как команда. |
| `typeof null` | `"object"` | `object` | string | Историческая особенность языка: `null` — примитив, но `typeof` даёт `"object"`. Результат `typeof` всегда строка. |
| `typeof NaN` | `"number"` | `number` | string | `NaN` — специальное значение типа number. Поэтому `typeof x === "number"` не гарантирует корректное число. |

## 6. Задание 3. Сводка выполнения задач

**Логика решения (`js/progress.js`).** Порядок проверок важен:

1. `Number.isInteger()` для обоих значений — отсекает строки (`"5"`), `NaN`, `Infinity`, дроби. Метод не преобразует типы.
2. Отрицательные значения.
3. Верхняя граница `totalTasks <= 1000`.
4. `completedTasks <= totalTasks`.
5. Если `totalTasks === 0` — «Задач пока нет» (деления на ноль не происходит).
6. Иначе считаются остаток, процент `completed / total * 100` (`toFixed(1)` только при выводе) и статус по исходным количествам.

Цепочка `if / else if` гарантирует, что после сообщения об ошибке обычная сводка не выводится.

Осталось: 12
Прогресс: 33.3%

## 7. Задание 4. План по дням

**Логика решения (`js/plan.js`).** Сначала все проверки (как в задании 3 плюс
`dailyLimit` — целое от 1 до 1000), и только потом цикл `while`. Проверка
`dailyLimit >= 1` гарантирует завершение цикла: на каждой итерации остаток уменьшается
хотя бы на 1. Количество задач на день — `Math.min(dailyLimit, remainingTasks)`,
поэтому в последний день не выполняется больше, чем осталось, и остаток не становится
отрицательным. Если остаток 0, цикл не выполняется ни разу и выводится «Потребуется дней: 0».

## 8. Задание 5. Отладка

**Исходный вывод (до исправления):**

```text
Выполнено: 32
Осталось: -24
Контрольная сумма: 6
```

Исключения не было, но результат неверный. Это показывает, что «программа не упала» ≠ «программа работает правильно».

**Наблюдения в отладчике (Sources):**

- Точка останова на строке `const completedTotal = completedText + additionalText;`.
  До выполнения строки: `completedText = "3"` (string), `additionalText = "2"` (string).
- После **Step over**: `completedTotal = "32"`, тип **string**. Затем `"8" - "32"` → `-24`
  (минус приводит строки к числам).
- Точка останова внутри цикла `controlSum += taskNumber`: остановки были при
  `taskNumber = 1, 2, 3` (`controlSum` до сложения: 0, 1, 3). При `taskNumber = 4` условие
  `4 < 4` ложно, тело не выполняется, поэтому сумма 1+2+3 = 6.

**Иллюстрация:** `screenshots/debug-breakpoint.png` — _сделать самостоятельно: в Chrome
DevTools → Sources остановиться на строке `completedTotal` и снять экран, где видны строка
остановки и значения в Scope._

| Ошибка | Что наблюдалось | Причина | Исправление | Результат после исправления |
|---|---|---|---|---|
| Обработка количества задач | «Выполнено: 32», «Осталось: -24» | Сложение двух строк `"3" + "2"` — это конкатенация | `Number(completedText) + Number(additionalText)`, `Number(plannedText) - completedTotal` | Выполнено: 5, Осталось: 3 |
| Граница цикла | «Контрольная сумма: 6» | Условие `taskNumber < 4` не включает 4 | Условие `taskNumber <= 4` | Контрольная сумма: 10 |

## 9. Дополнительное задание (вариант А): данные поступают строками

Файл `js/progress-input.js`. Порядок обработки:

1. `typeof ... !== "string"` — отсекает `null`, `undefined`, числа; поэтому `trim()` не вызовет исключение.
2. `trim()` — убрать пробелы по краям.
3. Пустая строка после `trim()` — ошибка «пустой ввод».
4. `Number()` и затем все правила задания 3 (`Number.isInteger`, диапазоны).

**Почему недостаточно `Number()` и проверки на неотрицательность:** `Number("")` и
`Number("   ")` дают `0` — пустой ввод «молча» превратился бы в допустимое значение.
`Number("abc")` даёт `NaN`, а `NaN >= 0` — `false`, но и `NaN < 0` — тоже `false`, так что проверка
«не отрицательно» его пропустит. `Number("2.5")` и `Number("Infinity")` дают неотрицательные,
но не целые числа. `Number(null)` даёт `0`. Нужны проверки типа, пустоты и целочисленности.

| Проверка | Входные данные | Ожидаемый результат | Фактический результат | Итог |
|---|---|---|---|---|
| Обычные строки | `"12"`, `"5"` | Сводка 12/5, 41.7% | Всего 12; Осталось 7; 41.7%; В работе | Пройдено |
| Пробелы по краям | `"  12 "`, `" 5"` | Как для `"12"`, `"5"` | Всего 12; Осталось 7; 41.7% | Пройдено |
| Пустая строка | `""`, `"0"` | Ошибка | Ошибка: пустой ввод | Пройдено |
| Строка из пробелов | `"   "`, `"0"` | Ошибка | Ошибка: пустой ввод | Пройдено |
| Не число | `"abc"`, `"0"` | Ошибка | Ошибка: значение не является целым числом | Пройдено |
| Дробь | `"5"`, `"2.5"` | Ошибка | Ошибка: значение не является целым числом | Пройдено |
| Бесконечность | `"Infinity"`, `"0"` | Ошибка | Ошибка: значение не является целым числом | Пройдено |
| null | `null`, `"0"` | Ошибка без исключения | Ошибка: входные данные должны быть строками | Пройдено |
| undefined | `"5"`, `undefined` | Ошибка без исключения | Ошибка: входные данные должны быть строками | Пройдено |
| Собственная: нули | `"0"`, `"0"` | Задач пока нет | Задач пока нет | Пройдено |
| Собственная: минус | `"-3"`, `"0"` | Ошибка | Ошибка: количество задач не может быть отрицательным | Пройдено |

## 10. Вывод

Освоены запуск одного и того же кода в Node.js и браузере, работа с `const`/`let`,
явное преобразование типов, проверка входных данных через `Number.isInteger` и диапазоны,

сверять с ожиданием, а не только смотреть, что программа «не упала».

## 4. Модель данных и функции

**Модель задачи:** `{ id, title, completed, priority }`

- `id` — положительное безопасное целое (`Number.isSafeInteger(id) && id > 0`), уникальное в списке;
- `title` — строка, после `trim()` длина 1…100; сохраняется очищенная строка;
- `completed` — boolean, у новой задачи всегда `false`;
- `priority` — строго `"low"`, `"medium"` или `"high"` (по умолчанию `"medium"`).

**Распределение файлов:**

| Файл | Что делает |
|---|---|
| `src/data.js` | Только данные: `demoTasks`, `variantNumber`, `variantTasks`. |
| `src/task-service.js` | Девять функций. Нет `console.log`, DOM и глобального списка; работает только с аргументами. Внутренние помощники `validateId` и `normalizeTitle` убирают дублирование проверок. |
| `src/task-extra.js` | Расширение: `getPrioritySummary`. |
| `src/main.js` | Сценарии: вызывает функции, хранит текущее состояние, выводит результаты. |
| `checks.js` | 35 готовых проверок + 4 собственные + 3 проверки расширения. |

**Контракты:**

| Функция | Успех | Ошибка |
|---|---|---|
| `createTask(id, title, priority)` | `{ ok: true, task }` | `{ ok: false, error }` |
| `findTaskById(tasks, id)` | объект задачи (`find`) | `undefined` |
| `getPendingTasks(tasks)` | новый массив (`filter`) | — |
| `getTaskTitles(tasks)` | новый массив строк (`map`) | — |
| `getTaskStats(tasks)` | `{ total, completed, pending, progress }` | — |
| `addTask` / `setTaskCompleted` / `renameTask` / `removeTask` | `{ ok: true, tasks: новыйМассив }` | `{ ok: false, error }` |

`addTask` — через `createTask` + spread массива; `setTaskCompleted` и `renameTask` — через `map` и spread объекта; `removeTask` — через `filter`. Нигде нет `push`, `splice` и присваиваний свойствам входных объектов.

**Почему id не равен индексу:** индекс — текущая позиция в массиве; он сдвигается после удаления. `id` — постоянный идентификатор записи. В `demoTasks` у задачи с `id = 4` индекс 1, а `tasks[4]` вообще `undefined`. Поэтому поиск — только через `find`.

**Почему `getTaskStats` возвращает число:** расчёт и отображение — разные задачи. Число можно сравнивать и использовать дальше (например, в проверке `33.333… ≈ 100/3`), а `toFixed(1)` возвращает строку, нужную только при выводе.

**Какие объекты копируются при изменении задачи:** создаётся новый массив (`map`) и новый объект **только для изменяемой задачи** (`{ ...task, completed }`). Остальные объекты переиспользуются как есть — их никто не меняет. Это проверено собственной проверкой С2.

## 9. Вывод

По сравнению с ПР1 код разделён на функции с явными входами и `return`, а данные — на объекты и массивы. Модуль `task-service.js` не печатает и не хранит состояние, поэтому одни и те же функции проверяются автоматически и будут без изменений использованы в браузере (ПР3).

Неизменность данных проверена тремя способами: сравнением снимка исходного массива, проверкой ссылок (новый массив и новый объект изменённой задачи) и замороженными входными объектами в проверке 33. Исправленная ошибка — пропущенный `return` в стрелочной функции: код «считал», но ничего не возвращал.
